## Load multiple texture packs at the same time

Luanti now supports loading multiple texture packs at the same time.
The order of the texture packs can be rearranged in the refined 'Content' tab in the main menu.
This changes prioritization of textures, so textures from the first pack in the
list will take priority, and if a texture is not found there, it will be
searched for in the next pack in the list, and so on. 

{% include figure.html src="/static/blog/5.18.0/content_tab.png" caption="New
interface for texture packs in the Content tab in the main menu" %}

## Translating to English is now possible 

Starting with this release, developers can now translate their games and mods
from their native language to English. By default, Luanti will still assume that
the game or mod is in English, but developers can now set the source language in
their translation files. To learn more, check out the [Lua API documentation](https://api.luanti.org/translations/#monolingual-translations-non-english-source-locale).

## Lua API to customize the world lighting

It is now possible for mods to customize the world lighting in Luanti using the
Lua API. This gives developers more freedom in their games and mods and players
more immersive experiences. 

{% include figure.html src="/static/blog/5.18.0/lighting.webp" caption="Comparison between world lighting in 5.17.0 and 5.18.0 in the game 'Minetest Classic'" %}

## Formspec: New `listimages` element, new editable style

The new `listimages` formspec element allows developers to style inventory slots
with textures, giving them more freedom to customize the look of their
inventories and fit their styles better.
Check out the [Lua API documentation](https://api.luanti.org/formspec/#listimagesslot_bgimg_normalslot_bgimg_hover)
for more information.

{% include figure.html src="/static/blog/5.18.0/listimages.jpg" caption="Example of the new listimages formspec element" %}

## Main Menu: Prevent users from completely disabling the Lua sandbox

The setting called "Enable mod security" to toggle the mod Lua sandbox has been
removed from the main menu, as it is a security risk to disable it. In contrast
to `secure.trusted_mods`, the setting gave *all* mods direct access to the host
system, which could be exploited by malicious mods. Developers should always use
`secure.trusted_mods` or `secure.http_mods` for privileged access. If you
absolutely must disable the Lua sandbox, there is a new `--insecure-no-sandbox`
CLI flag. Additionally, it is now impossible on Android to disable the Lua
sandbox and there is a warning in the main menu for the `secure.trusted_mods`
setting.

## Re-added the client setting to disable digging particles
This setting was removed in 5.11.0 and has now been re-added to give players
more control over their client and visual experience. It can be found in the
"Effects" section of the settings menu.

## Bug Fixes, Performance Improvements, and Other Changes 

As always, this release contains many bug fixes, performance improvements, and
other changes. There is also a new dependency: `libzip`, which is now required
to build Luanti. This is the foundation for future work on exporting and
importing worlds. A regression regarding collision checks was fixed, which could
cause entities to fall through the ground when lag spikes occurred.
